Low-fidelity wireframe for review before building. Click machines, variant numbers and keys to see which code the browser shows. There's no audio here; the real page plays each sound as you click it, over whatever is already playing. Orange italic text is an annotation, not UI.

The code bar always shows the exact Strudel code for the last sound you clicked. "Open in sandbox" adds it as a new part in your current project (a normal GUI edit, highlighted).

The browser is also reachable from the part you're editing, so you can swap a sound without leaving the code. It opens as a side drawer, already showing the part's own bank, and "Use" writes into that part.

Picking another machine and pressing Use changes only the .bank("…") text; the bank string flashes in the code. Variant buttons in the drawer write bd:2 into the row.

Try it: hold ⌘ (or Ctrl) and every dictionary word on the page gets a dotted underline. Hover one to see its definition. Without the key held, the text reads normally, with no clutter.

In a lesson

An acid line is a sawtooth wave through a low-pass filter with lots of resonance. Each note's envelope opens the filter, and an accent opens it further.

Set the tempo to 126 BPM and put the kick on every beat: four on the floor.

Terms are matched in lesson text, task hints, the reference page, sound-browser blurbs and control labels. Only the first mention per paragraph is marked, so a paragraph full of "kick" doesn't turn into a sea of dots.

In the code

note("c2 c3 eb2 c3").s("sawtooth").lpf(800).lpq(18)

With ⌘ held, function names and sound names in the editor are underlined too, and hovering explains them (the musical meaning, then a link to the Reference entry for the code details). ⌘-click opens the definition in the dictionary.
